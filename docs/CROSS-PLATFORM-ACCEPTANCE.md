# 双平台内部测试包人工验收

适用版本：`1.0.0`。核对日期：2026-11-11。当前已执行与待执行结果见[双平台记录](CROSS-PLATFORM-IMPLEMENTATION-REPORT.md)，本文是操作清单，不代表各项目已经通过。

## 1. 验收范围与记录

首轮目标：macOS 15.0+ Apple Silicon、Windows 11 x64。macOS 15 与 Windows 10 22H2 x64 实机结果单独登记。Intel Mac、Windows ARM、32 位、网络/UNC 和 exFAT 批量输出不在本轮范围。

每次填写验收包中的 `result.json`，记录包文件名、SHA-256、构建信息、系统版本、CPU/内存、验收人、日期、操作结果和异常。将“构建通过”“自动检查通过”“人工验收通过”分开；未执行项保留 `pending`。有失败时附步骤、截图和日志，不以跳过用例视为通过。

## 2. 获取、安装与启动

### 获取包

在代码已提交推送的版本上，打开 GitHub → Actions → **Desktop internal test packages** → Run workflow。待对应平台任务成功，从 Artifacts 下载：

- `Videome-<平台>-<运行号>`：安装包、`SHA256SUMS.txt`、`build-info.json`、日志和 `manual-acceptance/`。
- `media-<平台>-<运行号>`：开发或重建所需媒体资源；安装包用户无需额外安装。

本机 Mac 包也可由 `release/` 取得。验收前核对摘要并保留构建信息；使用尚未结束的构建或旧版文档副本会导致结果无法对应。

### Mac

挂载 DMG，拖入 Applications 后打开，或解压 App ZIP。不要只复制包内可执行文件。本包只有 ad-hoc 本地签名，无 Developer ID 或公证；若系统阻止首次启动，在确认来源后按系统的“隐私与安全性”入口处理，不关闭整体安全保护。

### Windows

先测试 `*-setup.exe`：管理员确认、选择安装目录、从开始菜单启动。再退出该版本，单独测试 `*-portable.exe`，避免单实例机制切换到已运行的旧窗口。

Portable 不主动注册文件关联，仍使用当前用户 AppData 保存任务。验收电脑无需 Node、FFmpeg、Homebrew 或 Visual Studio；确认应用只使用随包媒体工具。

## 3. 基础与工程操作

- 启动窗口正常，拖动、最小化、最大化和 100% / 150% 显示缩放下没有缺失按钮或白屏。
- 在独立、无恢复记录的用户环境首次启动：工程名“未命名工程”，空时间线、素材数 0、曲库为空，没有海岛片段或示例字幕。
- 有旧缓存时允许恢复旧内容；打开“项目 → 查看界面示例”应明确显示没有源文件，不把占位片段误报为真实素材丢失。
- 导入验收包中的 `素材 空格/长视频 测试.mp4`，缩略图和预览正常，双击加入时间线后左侧仍有该素材。
- 新建、打开和另存为菜单可用；工程位置显示完整路径、可复制，并能在 Finder / 资源管理器中定位。
- 在中文与空格目录保存，刷新或重开后工程与路径对应；“另存为”不改写原工程。
- 新建空白后素材库保留，等待超过 10 秒，原工程文件没有被自动备份覆盖；同目录只保留最新的带时间戳 `.autosave-时间戳.videome` 副本，“恢复切换前的工程”可找回刚才的内容和路径。
- 工程名 `CON`、`章节:第一集` 能保存为合法文件，显示名称保留。
- Windows 安装版双击 `.videome`，冷启动与已有窗口时均正确打开。Portable 使用应用内打开，不要求注册关联。
- 普通 H.264、HEVC、FFV1 MKV、VP9 WebM 分别导出，检查原声、中文标题和字幕，无乱码、黑段或声画错位。HEVC 播放器不支持时用兼容播放器验证，保留编码检查结果。
- 用“输出目录”打开成片位置。卸载后工程、最终视频与用户记录保留；再次安装可恢复记录，文件关联清理符合预期。

## 4. 智能配乐与本地分析

以下项目用于 1.0.0 桌面版功能验收。它们是操作清单，不代表已经执行通过；每项应在 `result.json` 或验收记录中单独记录。

- 在没有恢复记录的空工程中打开“我的曲库”，确认数量为 0，没有占位音乐或在线曲目。
- 导入一首普通本地音频，确认曲库立即登记，随后显示“分析中”并最终显示 BPM、节奏、能量和氛围；导入的智能配音音频带有 `dubbingSource` 时不进入曲库。
- 打开“智能配乐”，确认中央最多显示 3 首推荐，摘要显示当前视频分析状态；视频上下文完成后，目标 BPM、推荐分数和推荐原因会更新。
- 选择一首尚未入轨的音乐，调整音量、人声自动避让、淡入、淡出、曲目起始位置和“循环铺满视频”，点击试听，确认这些配置即时生效，并且暂停试听会同步暂停视频和时间线播放。
- 在试听通过后点击“使用这首”，确认使用相同配置替换或添加背景音乐片段；时间线选中新片段，撤销可以恢复原背景音乐。
- 默认检查“循环铺满视频”已开启；开启时片段时长跟随可见视频有效结束位置，关闭后片段时长滑块才可编辑。
- 修改 BPM、氛围、节奏或能量后重新打开工程，确认 `musicOverrides` 优先于自动识别；自动重新识别不会覆盖手动修正。
- 使用“重新分析”，确认状态提示经历分析中到推荐更新；已有音乐特征可复用本机缓存，视频分析完成后推荐重新排序。
- 删除单曲和“清空”操作只移除曲库及工程引用，不删除磁盘原文件；“清空”指清空我的曲库，不清空背景音乐轨道本身。两种操作都可以撤销。
- 在浏览器预览模式确认界面使用基础时长/手动标签推荐，并提示桌面版才提供本机媒体分析；没有 FFmpeg/ffprobe 时确认曲目保留并可手动修正。

分析缓存位于应用用户数据目录的 `music-analysis/`，不应出现在工程媒体目录，也不应产生网络上传记录。

## 5. 批量混剪

1. 打开面板，数量初始为空。填写 3、成片时长 6 秒、30 fps，先分析后生成，得到 3 条 180 帧结果及 JSON/CSV。
2. 数量分别填写 1、7；未填写或超出 1–1000 不能开始。展开高级设置，仅有镜头阈值字段，无额外说明段落。
3. 同源、同种子和同参数分别以并发 1/2/4 小批量执行，比较序列签名和耗时。并发不改变规划，不要求跨编码器文件摘要相同。
4. 暂停后活动项完成、等待项不再领取；继续按原序列生成。取消后无残余活动 FFmpeg 和半成品，成功视频保留。
5. 编码中从任务管理器结束测试 App，重开应显示可恢复；校验继续后成功项摘要和修改时间不变，失败重试不重做成功项。
6. 载入任意成功结果的代表工程，源片段连续、原声联动，可保存和再导出，原工程不被覆盖。
7. 用可写本地 NTFS / APFS 目录完成一批 200 条、30 秒/30 fps 测试，200 个签名唯一，每条 900 帧，全部完整解码。200 仅为验收负载，界面数量仍可自由填写。
8. 分别小批量检查无音轨、短源循环、旋转与 VFR；HDR 应明确拒绝。
9. 关闭面板或刷新界面后任务继续；退出整个 App 后允许中断并在重启后恢复，不要求关机后后台继续编码。

固定素材的批量脚本仅输出 640×360，不能替代 Windows 实际桌面操作与目标分辨率性能验收。参数和输出规则见[批量说明](BATCH-MIX.md)。

## 6. Windows 源码开发验收

此项需要源码环境，与安装包用户操作分开。安装 Node.js 24，在 cmd 和 PowerShell 分别检查：

```sh
npm ci
npm run media:prepare
npm run media:check
npm run desktop:dev
```

记录启动、Ctrl+C 退出及子进程清理结果，再执行：

```sh
npm test
npm run dist:win
npm run verify:package
```

不要用“安装版能打开”代替“源码开发可运行”，也不要用 Windows Server CI 成功代替 Windows 11/10 人工验收。媒体准备、命令和资源导入细节见[开发与交付](DEPLOYMENT.md)。

## 7. 故障与反馈

验证空间不足、权限拒绝和目标盘不可用时能暂停或报错；修复条件后继续，源文件内容变化应拒绝旧批次。冲突的正式同名文件不得被覆盖。先备份测试数据再模拟磁盘故障，NTFS 外接盘拔出与恢复单独记录。

不支持硬链接等操作的目录应在开始前拒绝，Windows UNC 输出应拒绝；不要把未支持文件系统上的失败改记为通过。

源码环境执行 `npm run diagnostics`。如批次缺失，将 `VIDEOME_USER_DATA` 指向 App“工程位置”显示的实际用户数据目录后重跑。仅有 Windows 安装包时使用验收材料中的 `收集Windows诊断.ps1`；默认输出到桌面 `Videome-diagnostics`。执行策略阻止时可打开脚本检查并手动执行命令，无需更改全局策略。

反馈附 `result.json`、包摘要、`build-info.json`、系统版本、步骤、截图、失败批次清单及诊断文件。清单可能包含素材路径和错误细节，发送前可检查。Mac 本机结果、macOS 15 实机结果、Windows CI 和 Windows 人工结果分别记录。
