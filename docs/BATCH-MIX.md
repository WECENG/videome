# 批量自动混剪

适用版本：`0.1.0 Preview`。核对日期：2026-11-05。桌面右上角“批量混剪”可将一个本地长视频切片、随机重组为独立 MP4；浏览器预览不提供主进程批量队列。

## 1. 操作流程与参数

1. 选择源视频和输出目录，填写生成数量、片段时长、成片时长、种子和并发。
2. 点击“分析并生成方案”。后台计算源指纹、探测视频区间、识别镜头并生成全部唯一序列；分析可取消。
3. 查看切片数、唯一序列数、帧对齐时长、空间预算及降级信息，再点击“开始生成”。
4. 从历史批次暂停、取消、重试失败项或“校验并继续”；源文件移动后可“重新定位源视频”。
5. 对成功结果预览、复制路径或“编辑”源切片工程；“输出目录”打开该批次文件夹。

| 参数 | 界面默认 / 约束 |
| --- | --- |
| 生成数量 | 初始为空，必填 `1–1000` 整数 |
| 片段时长 | 约 3 秒，可设 `0.1–3600` 秒 |
| 成片时长 | 30 秒，可设 `0.1–3600` 秒；最终按帧对齐 |
| 输出帧率 | 30，可选 24 / 25 / 30 / 50 / 60 |
| 最大并发 | 自动 1–2 路，可选手动 1–8 路 |
| 种子 | 每次打开面板生成一个值，可手工固定，最长 200 字符 |
| 镜头对齐 | 默认开启 |
| 高级设置 | 镜头阈值默认 0.35；下方没有额外说明段落 |

输出画幅取创建批次时的当前工程宽高快照；批次创建后修改工程不改变该任务。视频码率当前界面不单独暴露，使用默认 12 Mbps；主进程参数接口支持 1–100 Mbps。输出宽高需为 2–7680 的偶数。

数量由用户决定，**200 仅是验收负载**。单条最多 64 个片段，源切片最多 100000；超出时应增大片段时长或降低成片时长。

## 2. 切片、精度与去重

镜头检测缩小画面并保留帧时间戳，以默认阈值 0.35 分析。固定切点在附近窗口内优先吸附镜头边界，窗口为片段长度的 25%，限制在 0.25–1 秒；没有合适切点则保持固定边界。短尾并入前段，短源保留一段循环使用。镜头分析失败会记录降级信息，无法读取视频则不能开始。

输出帧预算为 `N = round(请求秒数 × fps)`，实际时长为 `N / fps`。默认 30 秒、30 fps 为 900 帧。片段分配整数帧，最后一段裁切到剩余预算；在前后段容量允许时调整过短尾段，总帧数保持不变。

原声随画面同步重排，默认音量 100%，统一 48 kHz；迟到或提前结束的音频区间补静音。源文件无音轨则输出无音轨视频，不额外添加背景音乐。输入可为 VFR、小数帧率和带旋转信息的视频；批量只支持 SDR，检测到 HDR / Dolby Vision 时拒绝。

序列在编码前全部确定并保存。相同算法版本、素材切片结果、参数和种子可复现剪辑规划；并发完成顺序不影响序列。场景分析工具或切点变化可能改变规划；需要重做旧批次时使用保存的序列。

批次内以“片段 ID、源区间、使用帧数、顺序”生成签名去重，不要求不同成片素材重合率低。素材用完重新洗牌，多片段时避免相邻同段；单片段素材可能连续复用。最多尝试 `max(1000, 数量 × 50)` 次；仍不足时分析失败并提示已找到的唯一数量，不以重复结果补足。

## 3. 编码与并发

批量输出固定 H.264、`yuv420p`、MP4 `faststart`；有音轨时 AAC 256 kbps。Mac 优先 VideoToolbox，匹配硬件初始化错误时清理临时输出并以 `libx264` 重试一次；Windows 直接采用 `libx264`。实际编码器记录在清单中，不保证跨编码器文件字节相同。

自动并发默认 1。至少 4 核、16 GiB，输入/输出像素数不超过 1080p、帧率不高于约 30，且每条不超过 16 段时最多 2；前两条先单路执行。手动 1–8 表示最大活动输出数，验证和发布也占槽位。

每次执行一个批次，其余等待。普通导出与批量分析/执行共用资源锁；代理和缩略图在后台串行，批量占用时延后。解码和滤镜线程受限，软件 H.264 编码为 2 线程。更多并发不保证更快。

自动模式硬件回退后将后续并发降至 1。磁盘满、输出盘不可用或权限问题暂停整批；单条媒体错误记录失败而不阻止其他结果。

## 4. 暂停、取消与恢复

关闭面板或刷新渲染界面不会终止主进程中的任务。退出整个 App 会停止活动处理并保存可恢复状态，不能把关闭面板与退出应用混为一谈。

- **暂停**：停止领取新任务，允许活动输出完成。
- **取消**：终止活动媒体进程，清理临时文件，保留成功结果。
- **校验并继续**：核对源和成功输出后，继续尚未完成的原序列。
- **重试失败项**：保留成功项，只重排需要重做的状态，不重新随机规划。
- **重新定位源视频**：接受 SHA-256 与原源内容相同的文件；内容改变必须新建分析。

媒体通过守护包装器执行，IPC 断开时尝试结束 FFmpeg。Mac 使用 SIGTERM 后超时 SIGKILL；包装器强制等待约 4 秒，父级兜底约 5 秒。Windows 按本应用创建的 PID 终止进程树，不能假定具有 POSIX 信号语义。

启动时将遗留活动批次标为可恢复。分析阶段退出且尚未保存完整序列的批次需重新分析。恢复输出时校验摘要，不覆盖冲突的正式文件；不完整临时文件删除后按原序列重做。

## 5. 文件与空间

每批创建独立子目录，示例：

```text
选择的输出目录/
└── Videome-时间-批次ID/
    ├── mix-0001.mp4
    ├── mix-0002.mp4
    ├── batch-manifest.json
    ├── batch-manifest.csv
    └── 混剪-批次-序号-时间.videome    按需创建
```

权威清单位于 `userData/batch-mix/<jobId>/job.json`，保留 `.bak`。输出目录 JSON 是副本，CSV 是派生清单，不能代替权威状态。开始前和派发时检查实际输出盘，预留预计剩余输出的 20% 空间。

例如 200 条 × 30 秒 × 默认码率，预算约 9.192 GB（8.56 GiB）；加 20% 后约需 11.03 GB 可用空间。预算不是实际文件大小，估算也会为无音轨源预留音频预算。

输出先独占写 `.partial`，完成完整解码、视频流/帧数/时长、音频与 SHA-256 检查后，以硬链接独占发布，再提交完成状态。首轮面向本地 APFS / NTFS，目录必须支持所需操作；Windows UNC、网络盘和 exFAT 批量输出不在支持范围。

清理任务记录保留已生成视频、输出目录清单和代表工程。镜头缓存可在无活动任务时单独清理。用户数据目录可从顶部“工程位置”面板查看。

## 6. 代表工程

默认入口选择序号最小的成功结果，也可逐条点击“编辑”。重建工程引用原视频的源区间，连续排列画面和联动原声，不把成片 MP4 当作单个片段替代源切片。

载入前将当前工程保存到 `userData/batch-project-recovery/`，代表工程使用独立 `.videome` 路径。MP4 用于快速预览，逐镜头编辑和再次导出使用代表工程。工程仍依赖源视频，删除或改动源文件会影响重建和编辑。

## 7. 验证

先按[开发说明](DEPLOYMENT.md)准备媒体工具。开发桌面冒烟脚本需要已有 5173 服务：

```sh
npm test
npm run build
node scripts/desktop-batch-smoke.cjs
npm run dist:mac
node scripts/desktop-batch-smoke.cjs release/mac-arm64/Videome.app/Contents/MacOS/Videome
```

性能验收可独立执行：

```sh
npm run acceptance:fixtures
node scripts/batch-acceptance.cjs "output/manual-acceptance/素材 空格/长视频 测试.mp4" "output/batch-check"
```

该脚本固定输出 640×360、30 秒/900 帧，运行 1/2/4 路各 4 条及 2 路 200 条，报告写入目标目录的 `acceptance-report.json`。进程树 RSS 采样不含系统硬件媒体服务，不代表整机峰值。两轮实测及限制见[批量验收记录](BATCH-MIX-ACCEPTANCE.md)。
